# 맥북에서 Essay 작업하기

윈도우 PC에서 하던 Essay 작업을 맥북에서 그대로 이어 가고, 맥 버전을 만들기 위한 안내입니다.
코드는 전부 GitHub 저장소 `brothrone/Essay` 에 있으니, 맥북에서는 받기만 하면 됩니다.

---

## 1. 처음 한 번만 준비

```bash
# 1) 개발 도구 (git 포함)
xcode-select --install

# 2) Homebrew 가 없다면 https://brew.sh 의 설치 명령을 먼저 실행

# 3) Node.js 22 (Electron 44 는 Node 20 이상 필요)
brew install node@22
# 설치가 끝나면 brew 가 알려 주는 PATH 추가 명령을 한 번 실행하고 터미널을 새로 연다
node -v     # v22.x 가 보이면 됨

# 4) GitHub 로그인 (brothrone 계정, 브라우저로 로그인)
brew install gh
gh auth login

# 5) Claude Code (맥북에서 이어서 작업할 때)
curl -fsSL https://claude.ai/install.sh | bash
```

AI 기능까지 시험하려면 앱이 실행하는 AI 도구도 맥에 있어야 합니다.
- Claude: 위 5번의 Claude Code 를 설치하고 `claude` 를 한 번 실행해 로그인
- Gemini: Antigravity CLI 맥 설치 방법은 공식 안내(antigravity.google)에서 확인 (윈도우는 `irm https://antigravity.google/cli/install.ps1 | iex`)

## 2. 코드 받기

```bash
cd ~/Desktop
git clone https://github.com/brothrone/Essay.git
cd Essay

# 커밋 작성자는 반드시 아래처럼 (실명 · 개인 이메일이 기록에 남지 않게)
git config user.name brothrone
git config user.email 261971426+brothrone@users.noreply.github.com

cd app
npm install
```

## 3. 실행해 보기

```bash
cd ~/Desktop/Essay/app
npm run dev        # 화면을 고치면 바로 반영되는 개발 실행
# 또는
npm run build && npx electron .
```

지금 코드는 **윈도우 전용**이라 맥에서 켜면 화면과 데이터 저장(문서/Essay 폴더)은 되지만, 아래가 아직 안 됩니다.
- 제목 표시줄 모양 (윈도우 버튼 자리를 기준으로 그려져 있음)
- AI 도구 찾기 · 설치 · 로그인 (윈도우 경로 · PowerShell 을 씀)
- AI 작업 취소 (윈도우의 `taskkill` 을 씀)

## 4. 맥 버전을 만들 때 고칠 곳 (2026-10-09 완료)

> 아래 표의 항목은 1.4.0 에서 모두 반영했습니다. 지금 코드는 `process.platform === 'darwin'`(`main.cjs` 의 `IS_MAC`, 화면은 `src/platform.ts`) 로 나뉘어 윈도우 · 맥에서 같이 돌아갑니다. 맥에서 한 일 요약:
> - AI 도구 찾기: 로그인 셸 PATH(`zsh -lc`) + `~/.local/bin` · `/opt/homebrew/bin` · `/usr/local/bin`. 자식 프로세스는 `detached` 로 띄워 묶음 종료.
> - 설치: 앱 안에서 `curl … | bash` 실행(진행 줄 표시). 터미널 작업은 `.command` 파일을 터미널 앱으로 열기. Node.js 는 Homebrew(없으면 nodejs.org 안내).
> - Gemini(agy) 로그인: `/usr/bin/expect` 가상 터미널로 agy 를 띄우고, Essay 창에 붙여넣은 코드를 파이프 → expect → 터미널 입력으로 넘김(맥의 `script` 는 stdin 이 파이프면 실패). 가짜 HOME 으로 코드 입력이 agy 에 닿는 것까지 확인(잘못된 코드 → 즉시 `invalid_grant` 로 끝남).
> - 창 · 메뉴: `hiddenInset` + 신호등 위치, 앱 메뉴 · 편집 메뉴 · 윈도우 메뉴, ⌘/ 도움말, Dock 메뉴 · 배지, 창을 닫아도 앱 유지.
> - 업데이트: 서명이 없어 Squirrel 은 끄고 GitHub 최신 릴리스 확인 → "새 버전 → 다운로드" 띠.
> - 빌드: `build.mac` arm64 · x64 dmg 따로(universal 은 두 배 용량이라 1.4.1 부터 나눔), bzip2(UDBZ) 압축, 한국어 · 영어 언어 파일만, `scripts/after-pack.cjs` 가 ad-hoc 서명(윈도우는 locales 정리). `release.sh` 가 맥 + 윈도우 파일을 같은 릴리스에 올림.
> - 남은 것: 애플 개발자 서명 · 공증(아래 5장). 그 전까지 처음 열 때 Gatekeeper 안내가 뜨는 건 정상.

원칙: **윈도우 동작은 그대로 두고**, 맥일 때만 다르게 동작하도록 `process.platform === 'darwin'` 으로 나눕니다.
아래 이름은 `app/electron/main.cjs` 안의 함수 · 상수 이름입니다 (줄 번호는 바뀌므로 이름으로 찾기).

### 메인 프로세스 (`app/electron/main.cjs`)

| 위치 | 지금 (윈도우) | 맥에서 할 일 |
|---|---|---|
| 맨 위 `app.setAppUserModelId` | 윈도우 알림 · 작업 표시줄용 | 윈도우에서만 실행 |
| `APPDATA` · `LOCALAPPDATA` | `AppData\Roaming` · `AppData\Local` | 맥에서는 쓰지 않도록 (AI 도구 찾는 경로에만 쓰임) |
| `whereBin` | `where.exe` 로 명령어 위치 찾기 | `/bin/zsh -lc "command -v 이름"` (맥에서 앱은 터미널 PATH 를 못 받으므로 로그인 셸로 찾기) |
| `findCli` · `findGemini` | `claude.exe` · `agy.exe` · `*.cmd` 경로 | `~/.local/bin/claude`, `~/.claude/local/claude`, `/opt/homebrew/bin`, `/usr/local/bin` 등 |
| `aiEnv` | PATH 를 `;` 로 이어 붙임 | `path.delimiter`(맥은 `:`) + `/opt/homebrew/bin` 등 추가 |
| `killTree` | `taskkill /T /F` | 자식 프로세스 묶음 종료 (`process.kill(-pid)` 등) |
| `claudeLoggedIn` | `.cmd` 이면 `cmd.exe` 로 실행 | 맥은 바로 실행 |
| `TERMINAL_ACTIONS` · `openTerminal` | PowerShell 창을 띄워 설치 · 로그인 | 맥 터미널 앱으로 (예: `.command` 파일을 만들어 `open` 으로 실행, 또는 `osascript` 로 Terminal 열기) |
| `ai:install` (`INSTALL_ACTIONS`) | `powershell.exe -Command "irm … \| iex"` | `/bin/zsh -lc "curl -fsSL … \| bash"` |
| `CONSOLE_INPUT_CS` · `handOverLoginCode` | Gemini 로그인 코드를 PowerShell 콘솔 입력 버퍼에 써 넣음 (C# `WriteConsoleInputW`) | **맥은 방식이 완전히 다름.** agy 는 파이프로 넘긴 입력을 읽지 않으므로, 가상 터미널(pty)에서 agy 를 띄우고 그 터미널에 코드를 써 넣는 방식이 필요 (예: `node-pty`). 맥북에서 직접 시험해야 하는 부분 |
| `WIN_ARG_LIMIT` (30,000자) | 윈도우 명령줄 길이 제한 | 맥은 훨씬 길게 허용되므로 늘려도 됨 |
| `createWindow` | `titleBarStyle: 'hidden'` + `titleBarOverlay`, `ICON_ICO` | `titleBarStyle: 'hiddenInset'` + `trafficLightPosition`, 아이콘은 `icon.png` |
| `buildMenu` | 메뉴 표시줄 숨김, 단축키만 | 맥은 맨 앞에 앱 메뉴(`role: 'appMenu'`)와 편집 메뉴(`role: 'editMenu'`)가 있어야 복사 · 붙여넣기(⌘C · ⌘V)가 동작 |
| `setJumpList` | 작업 표시줄 점프 목록 | 윈도우에서만. 맥은 `app.dock.setMenu` 로 같은 메뉴 가능 |
| `checkDeadlines` · `scheduleBadgeUpdate` | 알림 · 배지 | 맥에서도 그대로 동작 (Dock 배지) |

### 화면 (`app/src`)

- **제목 표시줄** `src/components/TitleBar.tsx` + `src/index.css` 의 `--titlebar-h`: 맥은 왼쪽 위에 신호등 버튼이 오므로 왼쪽 여백을 두고, 오른쪽 윈도우 버튼 자리는 비우지 않아도 됨.
- **단축키 표시** `Ctrl+N` · `Ctrl+1~8` 등 (`Sidebar.tsx`, `NewProjectModal.tsx` 등): 맥에서는 `⌘N` 으로 보이게. 단축키 자체는 메뉴에서 `CmdOrCtrl` 로 되어 있어 그대로 동작.
- **안내 문구**: `PowerShell`, `윈도우`, `작업 표시줄`, `Ctrl+A → Ctrl+C` 같은 말이 있는 곳 — `HelpDialog.tsx`, `AiSetup.tsx`, `AuthCodeDialog.tsx`, `InstallProgress.tsx`, `NewProjectModal.tsx`, `PostingCheck.tsx`, `WelcomeDialog.tsx`, `Settings.tsx`(테마 '윈도우 설정 따라가기').
  맥이면 '터미널', '시스템 설정', '⌘A → ⌘C' 로. 화면에서 지금 운영체제를 알 수 있도록 `preload.cjs` 의 `info` 에 `platform` 을 넣어 두면 편함.

### 빌드 설정 (`app/package.json` 의 `build`)

맥 아이콘은 `app/build/icon.icns` 에 이미 넣어 두었습니다. `build` 에 아래를 추가합니다.

```json
"mac": {
  "target": [
    { "target": "dmg", "arch": ["arm64", "x64"] },
    { "target": "zip", "arch": ["arm64", "x64"] }
  ],
  "icon": "build/icon.icns",
  "category": "public.app-category.productivity",
  "hardenedRuntime": true,
  "notarize": true,
  "artifactName": "Essay-${version}-${arch}.${ext}"
}
```

- `zip` 은 자동 업데이트용으로 꼭 있어야 합니다 (맥 자동 업데이트는 zip 을 받아 바꿈).
- `scripts` 에 `"app:build:mac": "npm run build && electron-builder --mac"` 를 추가해 두면 편합니다.

## 5. 서명 · 공증 · 자동 업데이트 (아직 안 함 — 지금은 ad-hoc 서명으로 배포)

지금 배포본은 `scripts/after-pack.cjs` 의 ad-hoc 서명(`codesign --sign -`)만 돼 있습니다. 그래서 처음 열 때 "확인되지 않은 개발자" 안내가 뜨고(시스템 설정 → 개인정보 보호 및 보안 → 그래도 열기), 맥 자동 업데이트 대신 새 버전 알림만 띄웁니다. 아래는 나중에 서명을 붙일 때의 안내입니다. 서명을 붙이면 `package.json` 의 `build.mac` 에서 `identity: null` · `notarize: false` 를 지우고 `hardenedRuntime: true` 로 바꾸고, `main.cjs` 의 `setupAutoUpdate` 에서 맥 분기를 지워 electron-updater 를 쓰면 됩니다.

- **Apple Developer Program 가입 (연 $99)** 이 사실상 필요합니다.
  - 서명이 없으면 맥이 "확인되지 않은 개발자" 경고로 실행을 막고, 사용자가 시스템 설정에서 따로 허용해야 합니다.
  - **맥 자동 업데이트는 서명된 앱에서만 동작합니다.**
  - 서명에는 개발자 실명 또는 사업자 상호가 표시됩니다 → 사업자 등록 후 **상호로 가입**하는 것을 권장 (익명 유지).
- 가입 후 'Developer ID Application' 인증서를 키체인에 받고, 공증용 값을 환경 변수로 둔 채 빌드합니다.

```bash
export APPLE_ID="애플 계정 이메일"
export APPLE_APP_SPECIFIC_PASSWORD="appleid.apple.com 에서 만든 앱 전용 암호"
export APPLE_TEAM_ID="팀 ID"
npm run app:build:mac
```

## 6. 배포 (윈도우 · 맥 같은 릴리스에)

- 버전은 하나로 맞춥니다: `app/package.json` 의 version 을 올리고, 윈도우 · 맥 파일을 **같은 태그 `v버전` 릴리스**에 올립니다.
- 윈도우는 `latest.yml`, 맥은 `latest-mac.yml` 을 읽어 업데이트를 찾습니다. 두 파일 모두 릴리스에 있어야 하고, 지우면 안 됩니다.
- 맥에서 배포: `app/scripts/release.sh` (토큰은 `gh auth token` 에서 가져옴). 지금은 `--win --x64` 만 만들도록 되어 있으니 맥 설정을 넣은 뒤 `--mac` 도 함께 만들도록 고칩니다.
  최근 electron-builder 는 맥에서도 윈도우 설치 파일을 만들 수 있어서, 맥북 한 대에서 두 운영체제용을 한 번에 올릴 수 있습니다. 맥에서 윈도우 빌드가 실패하면 윈도우 파일은 윈도우 PC에서 `release.ps1` 로 같은 버전에 올리면 됩니다.
- 소개 사이트 `docs/index.html`: 다운로드 버튼이 지금은 `.exe` 파일만 찾습니다. 맥용 `.dmg` 버튼을 추가하고, FAQ 의 "맥에서도 되나요?" 답을 바꿉니다. `docs/` 를 push 하면 사이트에 바로 반영됩니다.

## 7. 확인하는 법

```bash
cd ~/Desktop/Essay/app
npx tsc -b                 # 타입 검사
npx oxlint src electron    # 코드 검사
npx vite build             # 화면 빌드
```

- 내 실제 데이터를 건드리지 않고 시험하려면 시험용 데이터 폴더로 띄웁니다: `ESSAY_DATA_DIR=/tmp/essay-test npx electron .`
- 맥에서 확인할 것: 창 · 메뉴 · ⌘ 단축키, AI 도구 찾기 · 설치 · 로그인(특히 Gemini 로그인 코드 입력), 맞춤 공고 찾기, 새 자소서에서 공고 읽기, 자동 업데이트(서명 후).
- **윈도우가 깨지지 않았는지**도 확인해야 합니다. 맥에서 만든 변경은 윈도우 PC에서 한 번 실행해 보거나, 최소한 윈도우 분기 코드를 건드리지 않았는지 살펴봅니다.
