# Essay 서버 (Cloudflare Workers + D1)

`server/` 폴더. 앱 밖에서 돌아가는 작은 서버로, 무료 요금제 안에서 돌아가게 만들었다.

## 지금 상태 (2026-10-10)
- 배포됨: `https://essay-api.aaxel0713.workers.dev` (Cloudflare 계정 `brothrone`, D1 `essay` · APAC). 실제 서버에서 `npm test` 통과, 시험 의견은 지움.
- 운영 비밀 값(`ADMIN_TOKEN`, `IP_SALT`)은 Cloudflare 에 올렸고, 같은 값을 이 맥의 `server/.prod.vars`(저장소 밖, 본인만 읽기)에 보관. 잃어버리면 새로 만들어 `wrangler secret put` 하면 된다.
- 주소의 `aaxel0713` 은 계정에 원래 있던 workers.dev 하위 도메인이다. 앱 · 사이트에 이 주소를 넣기 전에 바꿀지(도메인 구입 또는 하위 도메인 변경) 정한다.

## 지금 하는 일
| 주소 | 하는 일 |
|---|---|
| `GET /health` | 서버가 살아 있는지 |
| `POST /v1/feedback` | 앱의 의견 받기. GitHub 계정 없이, 공개되지 않게 쌓는다 |
| `GET /v1/admin/feedback` | 개발자만: 받은 의견 보기 (`?status=new` · `read` · `done`, `?limit=`, `?before=<id>`) |
| `POST /v1/admin/feedback/<id>/status` | 개발자만: 의견 상태 바꾸기 `{"status":"done"}` |

- 의견 본문: `{"kind":"bug|idea|etc","message":"…","contact":"(선택)","app":{"version":"1.7.0","os":"macOS","ai":"gemini"}}`
- IP 는 저장하지 않는다. `IP_SALT` 로 섞은 해시만 남겨 같은 곳에서 연달아 보내는 것을 막는다(시간당 5개 · 하루 20개, `wrangler.toml` 의 `[vars]`).
- `website` 칸이 채워진 요청은 자동 스팸으로 보고 받은 척만 한다(앱 화면에는 이 칸이 없다).
- 관리 주소는 `Authorization: Bearer <ADMIN_TOKEN>` 이 있어야 열린다.
- 아직 앱은 이 서버를 쓰지 않는다. 배포해서 주소가 생기면 의견 보내기 창이 이 서버로 보내도록 앱을 고쳐 릴리스한다(주소는 `docs/app-config.json` 에 넣어 앱 재배포 없이 바꿀 수 있게).

## 로컬에서 돌려 보기
```bash
cd server
npm install
npm run db:local          # 로컬 데이터베이스에 표 만들기
npm run dev               # http://localhost:8787
npm test                  # 다른 터미널에서: 의견 받기 · 거절 · 횟수 제한 · 관리 잠금 확인
```
로컬 비밀 값은 `server/.dev.vars`(저장소에 안 올라감)에 `ADMIN_TOKEN=…`, `IP_SALT=…` 로 둔다.

## 처음 배포 (한 번만)
Cloudflare 계정이 필요하다(무료). 계정 만들기와 로그인은 직접 한다.
```bash
cd server
npx wrangler login                    # 브라우저에서 Cloudflare 로그인 · 허용
npx wrangler d1 create essay          # 나온 database_id 를 wrangler.toml 에 넣는다
npm run db:remote                     # 실제 데이터베이스에 표 만들기
npx wrangler secret put ADMIN_TOKEN   # 긴 무작위 문자열 (관리 열쇠, 따로 잘 보관)
npx wrangler secret put IP_SALT       # 긴 무작위 문자열
npm run deploy                        # https://essay-api.<계정 하위 도메인>.workers.dev
npm test -- https://essay-api.<…>.workers.dev   # ADMIN_TOKEN 환경 변수와 함께
```
- 무작위 문자열 만들기: `node -e "console.log(require('crypto').randomBytes(24).toString('base64url'))"`
- **익명 유지 주의**: `workers.dev` 주소에는 계정의 하위 도메인이 들어간다. 처음 정할 때 실명 · 이메일이 드러나지 않는 이름(예: `brothrone`)으로 정한다. 도메인을 사면 그 주소로 바꾸면 된다.

## 받은 의견 보기
```bash
ADMIN_TOKEN=$(sed -n 's/^ADMIN_TOKEN=//p' server/.prod.vars)
curl -s -H "Authorization: Bearer $ADMIN_TOKEN" "https://<서버 주소>/v1/admin/feedback?status=new" | jq
```
또는 `npx wrangler d1 execute essay --remote --command "SELECT id, created_at, kind, message FROM feedback ORDER BY id DESC LIMIT 20"`.

## 도메인을 사면
1. Cloudflare 대시보드에서 도메인을 산다(Cloudflare Registrar, 원가 판매) 또는 다른 곳에서 산 도메인을 Cloudflare 에 붙인다.
2. `wrangler.toml` 의 `routes` 주석을 풀고 `api.<도메인>` 으로 바꿔 `npm run deploy`.
3. 앱 · `docs/app-config.json` 의 서버 주소를 새 주소로. 사이트(GitHub Pages)도 같은 도메인으로 옮길 수 있다(`docs/CNAME`).
4. 도메인이 생기면 Cloudflare Email Routing 으로 `help@<도메인>` 같은 받는 메일 주소도 무료로 만들 수 있다.

## 나중에: 결제와 라이선스 키 (CLAUDE.md 남은 일 2)
카드 결제 자체는 PG(나이스페이 등)가 받고, 이 서버는 **결제가 진짜인지 확인하고 키를 내주는 일**을 맡는다. PG 의 "결제 후 키 자동 발송 없음" 문제를 여기서 채운다.
1. 사이트 구매 페이지 → PG 결제창에서 결제
2. PG 가 서버로 결제 완료 알림(웹훅) → 서버가 PG API 로 주문 · 금액을 다시 확인(알림만 믿지 않는다)
3. 서버가 라이선스 키를 만들어 D1 에 저장 → 결제 완료 화면에 키를 보여 주고 메일로도 보냄
4. 앱은 키를 넣으면 서버에 확인(기기 수 제한, 환불되면 키 끔). 인터넷이 안 될 때도 쓸 수 있게 확인 결과를 서명해 앱에 저장
- 먼저 필요한 것: 사업자 등록, 통신판매업 신고, PG 가맹 심사(사이트에 사업자 정보 · 환불 규정이 있어야 함, 자기 도메인이 있으면 심사에 유리), 손님에게 메일을 보낼 발송 서비스.
- PG 키 같은 비밀 값은 모두 `wrangler secret put` 으로만 넣고 저장소에는 넣지 않는다.
