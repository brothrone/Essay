# Essay 서버 (Cloudflare Workers + D1)

`server/` 폴더. 앱 밖에서 돌아가는 작은 서버로, 무료 요금제 안에서 돌아가게 만들었다.

## 지금 상태 (2026-10-10)
- 배포됨: `https://api.essay.win` (도메인 essay.win 은 이 Cloudflare 계정에서 2026-10-10 구입, Cloudflare 계정 `brothrone`, D1 `essay` · APAC). 실제 서버에서 `npm test` 통과, 시험 기록은 지움.
- 운영 비밀 값(`ADMIN_TOKEN`, `IP_SALT`)은 Cloudflare 에 올렸고, 같은 값을 이 맥의 `server/.prod.vars`(저장소 밖, 본인만 읽기)에 보관. 잃어버리면 새로 만들어 `wrangler secret put` 하면 된다.
- 계정 이름이 들어가는 `*.workers.dev` 주소와 미리보기 주소는 꺼 두었다(`wrangler.toml` 의 `workers_dev = false`). 다시 켜지 않는다.
- `docs/app-config.json` 의 `api.baseUrl` 에 `https://api.essay.win` 을 넣어 1.8.0 이상 앱에서 기능이 켜졌다(앱은 하루 한 번 설정을 받는다).

## 지금 하는 일
| 주소 | 하는 일 |
|---|---|
| `GET /health` | 서버가 살아 있는지 |
| `POST /v1/feedback` | 앱의 의견 받기. GitHub 계정 없이, 공개되지 않게 쌓는다 |
| `POST /v1/stats` | 익명 사용 통계. 기기마다 하루 한 줄(기능 이름별 횟수 · 버전 · 운영체제 · AI 종류), 같은 날을 다시 보내면 덮어씀 |
| `POST /v1/errors` | 오류 보고. 같은 오류 · 같은 버전은 한 줄로 묶어 횟수와 겪은 기기 수만 센다 |
| `POST /v1/questions` | 회사별 자소서 문항 보태기. 회사 · 직무 · 시기 · 문항 · 사이트 이름만(공고 본문 · 주소는 안 받음) |
| `GET /v1/questions?company=&position=` | 회사 이름으로 모인 문항 찾기 (표기가 달라도 찾음: (주) · 공백 무시, 직무가 맞는 것 먼저, 18개월 안) |
| `GET /v1/admin/summary?days=30` | 개발자만: 날짜별 사용자 수, 버전 · 운영체제 · AI 분포, 기능별 사용 횟수, 새 의견 · 새 오류 수 |
| `GET /v1/admin/feedback` · `/errors` · `/questions` | 개발자만: 목록 (`?status=new`, `?limit=`) |
| `POST /v1/admin/feedback/<id>/status` · `/errors/<id>/status` | 개발자만: 상태 바꾸기 `{"status":"done"}` |
| `POST /v1/admin/questions/<id>/hide` | 개발자만: 잘못된 문항 묶음 숨기기 `{"hidden":true}` |

- 앱(1.8.0~)은 서버 주소를 `docs/app-config.json` 의 `api.baseUrl` 에서 받는다. **비어 있으면 아무것도 보내지 않고 화면도 예전과 같다.** 주소를 넣고 push 하면 앱이 하루 안에 받아 의견 보내기([보내기] 버튼) · 개선 돕기 동의 창 · 설정의 [개선 돕기] · 새 자소서의 문항 모음이 켜진다. 시험할 때는 앱을 `ESSAY_API_URL=http://localhost:8787` 로 띄운다.
- 통계 · 오류 · 문항 모음은 사용자가 [개선 돕기]에서 고른 것만 보낸다(처음 한 번 묻고, 설정에서 바꿈). 문항 모음은 동의한 사람만 찾아볼 수도 있다. 앱 코드: `app/electron/community.cjs`, `app/src/community.ts`.
- 기기 번호는 앱이 처음 실행 때 만든 무작위 값이고, 서버는 기능마다 다른 값으로 섞어 저장해 통계 · 오류 · 문항 기록을 서로 이을 수 없다. IP 는 저장하지 않는다(횟수 제한용 해시만, 이틀 뒤 지움).
- 오류 메시지 속 사용자 경로 · 메일 주소는 앱과 서버가 두 번 지운다.
- 같은 곳에서 연달아 보내면 막는다: 의견 시간당 5 · 하루 20, 문항 시간당 20, 오류 시간당 20 (`rate` 표, 매일 정리).
- 문항 모음은 누구나 보탤 수 있어서 엉터리가 섞일 수 있다. 관리 주소로 보고 숨긴다. 채용 사이트 글을 모아 나누는 것이라 사이트 약관 · 저작권 문제가 생길 수 있어, 공고 본문은 받지 않고 문항 문장만 둔다.
- 400일 지난 통계와 이틀 지난 횟수 제한 기록은 매일 한 번(한국 시간 03:17) 지운다.

## 로컬에서 돌려 보기
```bash
cd server
npm install
npm run db:local          # 로컬 데이터베이스에 표 만들기
npm run dev               # http://localhost:8787
npm test                  # 다른 터미널에서: 의견 받기 · 거절 · 횟수 제한 · 관리 잠금 확인
```
로컬 비밀 값은 `server/.dev.vars`(저장소에 안 올라감)에 `ADMIN_TOKEN=…`, `IP_SALT=…` 로 둔다.

## 처음 배포 (한 번만)
Cloudflare 계정이 필요하다(무료). 계정 만들기와 로그인은 직접 한다.
```bash
cd server
npx wrangler login                    # 브라우저에서 Cloudflare 로그인 · 허용
npx wrangler d1 create essay          # 나온 database_id 를 wrangler.toml 에 넣는다
npm run db:remote                     # 실제 데이터베이스에 표 만들기
npx wrangler secret put ADMIN_TOKEN   # 긴 무작위 문자열 (관리 열쇠, 따로 잘 보관)
npx wrangler secret put IP_SALT       # 긴 무작위 문자열
npm run deploy                        # https://api.essay.win (wrangler.toml 의 routes)
npm test -- https://api.essay.win     # ADMIN_TOKEN 환경 변수와 함께. 끝나면 시험 기록을 지운다
```
- 무작위 문자열 만들기: `node -e "console.log(require('crypto').randomBytes(24).toString('base64url'))"`

## 도메인을 사면
1. Cloudflare 대시보드에서 도메인을 산다(Cloudflare Registrar, 원가 판매) 또는 다른 곳에서 산 도메인을 Cloudflare 에 붙인다.
2. `wrangler.toml` 의 `routes` 주석을 풀고 `api.<도메인>` 으로 바꿔 `npm run deploy`.
3. 앱 · `docs/app-config.json` 의 서버 주소를 새 주소로. 사이트(GitHub Pages)도 같은 도메인으로 옮길 수 있다(`docs/CNAME`).
4. 도메인이 생기면 Cloudflare Email Routing 으로 `help@<도메인>` 같은 받는 메일 주소도 무료로 만들 수 있다.

## 결제 · 이용권 (2026-10-10 만들어 둠, 아직 꺼짐)
사용자 결정: **정가 4,900원 → 지금 3,900원, 한 번 결제하면 계속 사용, 결제 전엔 앱을 못 씀, 결제를 켜기 전에 설치한 사람은 계속 무료**, 결제 수단은 **카카오페이 · 네이버페이만**(포트원에 각각 채널, 사업자 등록 예정). 고객 응대는 `guides/고객응대-매뉴얼.md`, 관리 명령은 `server/scripts/cs.sh`.

흐름
1. 앱 결제 화면 [구매하기] → 무작위 `ref` 를 붙여 `https://essay.win/buy.html?ref=…` 를 브라우저로 연다 (페이지는 읽자마자 주소창에서 ref 를 지운다)
2. 구매 페이지(`buy.html` + `buy.js`)가 `POST /v1/billing/options` 로 가격 · 쓸 수 있는 결제 수단(채널 키가 들어간 것만)을 받아 버튼을 보이고, 고른 수단으로 `POST /v1/billing/prepare {method}` 를 부르면, 서버가 **금액(PRICE)을 정해 포트원에 사전 등록**(`/payments/{id}/pre-register`)한 뒤 포트원 결제창(`PortOne.requestPayment`, `EASY_PAY` — 네이버페이는 상품 정보 `bypass.naverpay.productItems` 포함)을 띄운다 — 다른 금액으로는 결제 자체가 안 된다
3. `POST /v1/billing/complete` → 서버가 **포트원 API(`GET /payments/{id}`)로 상태 · 금액 · 상점을 다시 확인**하고 이용권 키(`ESSAY-XXXX-XXXX-XXXX-XXXX`, 2^80 가지)를 만든다. 금액이 다르면 키 없이 **자동 취소**. 결제 한 건에 키 하나(DB 고유 인덱스 — 동시에 여러 번 확인해도 하나)
4. 앱은 처음 2분은 3초, 그 뒤 10초마다(최대 30분) `POST /v1/license/claim {ref, device}` 로 물어 키와 **등록증(Ed25519 서명: 키 · 기기 · 확인 시각)** 을 받아 `userData/license.json` 에 두고 바로 열린다. 키를 직접 넣으면 `POST /v1/license/activate`
5. 앱은 인터넷이 없어도 공개 키(`app/electron/billing.cjs` 의 `PUBLIC_KEY`)로 등록증을 확인한다. 3일에 한 번 `POST /v1/license/check` 로 환불 여부를 보고 새 등록증을 받는다. **60일 넘게 확인 못 하면** "인터넷에 연결한 뒤 확인" 화면. 기기가 비워졌으면(고객 요청 초기화) 저장된 키로 자동 재등록
6. 포트원 웹훅 `POST /v1/billing/webhook` 은 **Standard Webhooks 서명**(`PORTONE_WEBHOOK_SECRET`, 5분 안 시각만)을 확인하고, 내용은 결제 번호로 다시 조회한다. 취소면 이용권 막음, **분쟁(차지백)** 이면 바로 막음
7. 매일 cron(`reconcile`)이 3일 안에 확인 못 한 결제를 포트원에서 다시 확인(창을 닫거나 웹훅이 안 온 경우), 30일 지난 미결제 주문을 지운다

'먼저 쓰던 사람' (결제를 켜기 전 설치)
- 앱이 서버에서 받은 설정에 `billing.enabled` 가 false 인 동안 켜지면 `POST /v1/license/legacy {device}` 로 **서버가 서명한 확인증(k: 'LEGACY')** 을 받아 `userData/billing-legacy` 에 둔다. 서버는 그 기기(해시)를 `legacy_devices` 에 기록
- 결제를 켠 뒤(`BILLING_LIVE=1`)엔 기록된 기기에만 다시 준다 → 파일을 만들어 흉내 내도 안 된다(1.9.9 가 남긴 날짜만 적힌 예전 표시도 서버 확인을 거침). 놓친 사람은 고객 응대 매뉴얼 I 대로 보상 키

보안 장치 정리
- 가짜 결제(`BILLING_MOCK`)는 ①로컬 설정 ②로컬 요청(Cloudflare 접속 IP 없음) ③포트원 비밀 값 없음 — 셋 다 맞을 때만
- 구매 페이지 요청은 `essay.win` 출처만 허용(CORS), 페이지는 CSP(인라인 스크립트 금지) · 다른 사이트 안에 숨겨 띄우기 막기 · 주소 전달(referrer) 막기
- 횟수 제한: 결제 준비 시간당 20, 확인 60, 키 직접 넣기 20(키 추측 방지), claim 900, 웹훅 600. 관리 열쇠 실패는 시간당 10번이면 막음
- 앱의 시험용 환경 변수(`ESSAY_BILLING` 등)는 패키지된 앱에선 무시, 구매 · 약관 페이지는 `essay.win` 주소만 연다
- 기록: 결제 · 취소 · 자동 취소 · 분쟁 · 관리자 조치는 모두 `billing_log` 에 남는다(`cs.sh log`)
- 앱 코드가 공개라 앱을 고쳐 결제 화면을 지우는 것까지는 막을 수 없다 — 돈 · 키 발급 · 환불은 서버에서만 결정되게 설계

시험
- 서버 `.dev.vars`: `BILLING_MOCK=1`, `PORTONE_STORE_ID` · `PORTONE_CHANNEL_KAKAOPAY` · `PORTONE_CHANNEL_NAVERPAY`(아무 값), `PORTONE_WEBHOOK_SECRET`, `LICENSE_PRIVATE_KEY`. 가짜 결제는 메일 `cancel@test.local` 면 취소, `short@test.local` 이면 100원 결제(금액 불일치)로 본다. `npm test` 에 결제 · 보안 항목 포함(동시 확인, CORS, 웹훅 서명, 금액 불일치 자동 취소, 환불, 기기 한도 등)
- 결제 켠 상태 시험: `npx wrangler dev --local --port 8787 --var BILLING_LIVE:1`
- 앱: `ESSAY_API_URL=http://localhost:8787 ESSAY_BILLING=1 ESSAY_BUY_URL=http://localhost:8765/buy.html ESSAY_NO_EXTERNAL=1`(개발 실행에서만 들음)

켜는 날 할 일
1. (사용자) 사업자 등록 · 통신판매업 신고 · 포트원 가입과 PG 심사(소프트웨어 이용권 판매 가능 여부 확인) · 정산 계좌
2. 포트원 콘솔에서 카카오페이 · 네이버페이(결제형) 채널을 만들고 `wrangler.toml` 의 `PORTONE_STORE_ID` · `PORTONE_CHANNEL_KAKAOPAY` · `PORTONE_CHANNEL_NAVERPAY` 채우기(한쪽만 먼저 해도 됨 — 키를 넣은 것만 버튼이 나옴), `npx wrangler secret put PORTONE_API_SECRET`, 포트원 콘솔 결제알림(Webhook) 주소 `https://api.essay.win/v1/billing/webhook`(버전 2024-04-25) + 비밀 값 `npx wrangler secret put PORTONE_WEBHOOK_SECRET` → `npm run deploy`

4. 포트원 테스트 채널로 카카오페이 · 네이버페이 결제창 각각 한 번 → 실 채널로 소액 결제 · 환불까지 한 번. 네이버페이는 실 검수 통과가 필요(결제 실패 문구를 가공하지 않고 보여 주기, 상품 정보 `categoryType` · `categoryId` 가 디지털 이용권에 맞는지 검수 때 확인)
5. 같은 날: `wrangler.toml` 의 `BILLING_LIVE` 를 "1" 로 deploy → `docs/app-config.json` 의 `billing.enabled` 를 true 로 push (앱이 하루 안에 받음) + `app-config-default.json` 도 true 로 바꾼 버전 배포(처음 켤 때 인터넷이 없는 새 설치 대비). 켜기 며칠 전엔 최신 앱이 퍼지도록 미리 배포해 두어 '먼저 쓰던 사람' 확인증이 쌓이게 한다
