# 고객 응대 매뉴얼 (결제 · 이용권)

Essay 이용권(정가 4,900원 → 3,900원, 한 번 결제 · 기기 3대) 관련 문의를 받았을 때 보는 문서예요.
구조와 보안 설계는 `guides/서버-안내.md` 의 "결제 · 이용권", 서버 코드는 `server/src/billing.ts`, 앱 쪽은 `app/electron/billing.cjs`.

---

## 0. 기본 원칙

- **답장 시간**: 결제 · 이용권 문제는 **당일**, 나머지는 24시간 안. 늦어지면 "확인 중이에요, 오늘 안에 알려 드릴게요" 먼저.
- **본인 확인**: 이용권 키 · 환불은 아래 중 **두 가지**가 맞을 때만 처리해요.
  - 결제 때 적은 메일
  - 결제 일시(대략)와 금액
  - 카드 승인번호 뒤 4자리 또는 카드사 이름 (카드 문자 · 영수증에 있음)
  - 이용권 키 앞 · 뒤 4자리
- **키는 통째로 공개된 곳에 쓰지 않아요.** 답장 메일 · 1:1 채팅에서만, 다른 사람 문의에 섞이지 않게.
- **모든 조치에는 이유를 남겨요.** `cs.sh` 의 메모 · 이유 칸은 필수. 서버 `billing_log` 에 남아 나중에 분쟁 때 근거가 돼요.
- **관대하게**: 3,900원 때문에 다투지 않아요. 애매하면 고객 편(환불 · 보상 키). 다만 같은 사람이 반복하면 기록을 보고 판단.
- **법이 정한 것**: 디지털 콘텐츠는 제공(이용권 등록) 뒤 청약철회 제한을 결제 전에 고지하고 동의를 받았어요(구매 페이지 체크 · 약관). 그래도 **하자(앱이 안 돌아감) · 중복 결제 · 미성년자 취소**는 무조건 환불.

## 1. 도구

```bash
cd mac/Essay/server
./scripts/cs.sh find <메일|키|결제번호>   # 먼저 이걸로 상황 파악 (주문 · 이용권 · 등록 기기 수 · 처리 기록)
./scripts/cs.sh summary                    # 매일: 매출 · 새 의견 · 자동취소 실패 · 분쟁
```

| 명령 | 언제 |
|---|---|
| `find <메일·키·결제번호>` | 모든 문의의 첫 단계 |
| `recheck <결제번호>` | 결제했는데 키가 안 나왔을 때 — 포트원 상태로 다시 맞춤 |
| `refund <결제번호> "<이유>"` | 환불 (포트원 취소 + 이용권 막기). 이유 필수 |
| `reset <키> "<메모>"` | 새 PC · 포맷 · 4대째 막힘 — 등록 기기를 비움. 쓰던 기기는 다음 확인 때 저절로 다시 등록 |
| `devices <키> <대수> "<메모>"` | 연구실 · 집 · 노트북 등 사정이 있으면 한도 늘림 (최대 10) |
| `grant <메일 또는 -> "<메모>"` | 새 이용권 만들기 (먼저 쓰던 사람 복구 · 보상 · 오류 사과) |
| `revoke <키> "<메모>"` / `restore` | 공유 · 재판매 · 도용 확인 시 막기 / 잘못 막았으면 풀기 |
| `forget <메일>` | 개인정보(메일) 삭제 요청 |
| `orders` · `log` | 최근 주문 · 처리 기록 |

- 포트원 콘솔(결제 내역 · 취소 · 분쟁 소명)은 웹에서. 결제 번호(`essay-…`)로 찾으면 돼요.
- 관리 열쇠는 `server/.prod.vars` 에만. 다른 PC · 채팅에 붙여넣지 않아요.

## 2. 상황별 대응

각 항목: **확인 → 조치 → 답장**. 답장은 짧은 해요체.

### A. "결제했는데 앱이 안 열려요"
1. `find <메일>` 또는 고객이 준 결제 시각으로 주문을 찾는다.
2. 주문 상태별:
   - `paid` + 키 있음 → 앱이 자동으로 못 받은 것. 키를 알려 주고 앱의 [이용권 키가 있어요]에 넣으라고 안내.
   - `ready` (결제 확인 전) → `recheck <결제번호>`. `paid` 가 되면 위와 같이. 포트원에도 결제가 없으면 실제로 결제가 안 된 것(카드 문자 확인 요청).
   - `failed` → 금액 불일치 자동 취소됨. 카드사에서 취소 문자가 갈 거라고 안내, 다시 구매 안내.
3. 답장:
   > 확인해 보니 결제는 정상으로 됐어요. Essay 결제 화면에서 [이용권 키가 있어요]를 누르고 아래 키를 넣어 주세요.
   > 이용권 키: ESSAY-XXXX-XXXX-XXXX-XXXX
   > 불편을 드려 죄송해요.

### B. "키를 잃어버렸어요" / "결제 완료 화면을 닫았어요"
1. 본인 확인(0번) 후 `find <메일>`. 메일을 안 적었으면 결제 일시 · 금액 · 카드 승인번호로 포트원 콘솔에서 결제 번호를 찾고 `find <결제번호>`.
2. 키를 알려 준다. 이미 그 PC 에 등록돼 있었다면 앱은 그대로 열려요(키는 다른 PC 에만 필요).
3. 답장:
   > 이용권 키를 찾아 드렸어요: ESSAY-XXXX-XXXX-XXXX-XXXX
   > 다른 PC 에서는 결제 화면의 [이용권 키가 있어요]에 넣으면 돼요. 메일 · 메모장에 보관해 두세요.

### C. "새 PC 에 넣으니 3대까지래요" / 포맷 · 기기 교체
1. `find <키>` 로 `devices` 수 확인.
2. `reset <키> "기기 교체: 고객 요청"` → 새 PC 에서 키를 다시 넣으면 등록. 예전 기기들도 계속 쓰면 다음 확인 때 자동으로 다시 등록되니, 3대 넘게 계속 쓰려는 상황이면 사정을 듣고 `devices <키> 4~5`.
3. 같은 키로 한 달에 여러 번 초기화 요청 → 공유 의심(M 항목).
4. 답장:
   > 등록된 기기를 비웠어요. 새 PC 에서 키를 다시 넣어 주세요. (이용권 하나로 기기 3대까지예요.)

### D. 환불 요청
| 상황 | 처리 |
|---|---|
| 결제 후 7일 안 · **앱에 등록 안 함** (`devices` 0) | 전액 환불 |
| 등록했지만 **앱이 그 PC 에서 실행 안 됨** (설치 오류 · 지원 안 하는 OS · Intel 맥) | 먼저 해결 시도 → 안 되면 전액 환불 |
| **중복 결제** (E) | 중복분 환불 |
| **미성년자**가 부모 동의 없이 결제 (법정대리인 취소) | 전액 환불 |
| 등록해서 써 보고 단순 변심 | 원칙은 청약철회 제한(결제 전 동의함). 다만 결제 후 7일 안이고 처음 요청이면 **환불해 주는 쪽**(3,900원 분쟁 비용이 더 큼). 반복 · 악용이면 정중히 거절 |
| AI(Claude · Gemini · ChatGPT) 한도 · 요금 문제 | Essay 가 파는 게 아니라고 설명, 앱 문제면 해결 지원. 원하면 7일 규칙대로 |
| 7일 지난 단순 변심 | 정중히 거절 (약관 3항) |

- 처리: `refund <결제번호> "<이유: 7일 내 미등록 / 실행 불가 / 중복 / 미성년자 / 변심(첫 요청)>"`
  → 포트원이 카드 취소를 하고, 이용권은 막히고, 앱은 다음 확인(최대 3일) 때 결제 화면으로 돌아가요.
- 카드 취소는 카드사마다 3~7영업일 걸려요(체크카드는 계좌로 환급).
- 답장(환불함):
  > 환불해 드렸어요. 카드사에 따라 3~7영업일 안에 취소돼요. 이용해 주셔서 감사했어요.
- 답장(거절):
  > 이용권은 디지털 상품이라 앱에 등록한 뒤에는 환불이 어려워요(결제 전에 안내 · 동의). 쓰시다 불편한 점이 있으면 알려 주시면 바로 고칠게요.

### E. 중복 결제 (두 번 눌러서 두 번 결제)
1. `find <메일>` 에 `paid` 주문이 둘 이상인지 확인.
2. **등록 기기가 없는 쪽**(또는 나중 것)을 `refund <결제번호> "중복 결제"`.
3. 답장: "두 번 결제된 것을 확인하고 한 건을 취소했어요. 3~7영업일 안에 카드사에서 취소돼요."

### F. 결제가 안 돼요 (카드 거절 · 오류)
- 대부분 카드사 · 결제 대행사 쪽 문제예요. 확인 순서:
  1. 해외 결제 차단은 상관없어요(국내 결제).
  2. 체크카드 잔액 · 한도, 카드사 앱의 온라인 결제 차단 여부.
  3. 다른 카드 · 간편결제로 다시.
  4. 브라우저 팝업 차단 해제(결제 창이 팝업으로 뜰 수 있음).
- 돈이 빠져나갔는데 실패로 나왔다 → `find` 로 주문 확인 후 `recheck`. 포트원에 결제가 있으면 A 처럼 키 지급, 금액이 이상하면 자동 취소돼요.

### G. 금액 불일치 자동 취소 (`summary` 에 `amount_mismatch` / `auto_cancel_failed`)
- 정상적으로는 거의 안 생겨요(금액을 포트원에 사전 등록). 생기면 누군가 결제 금액을 조작하려 했거나 결제 대행사 오류.
- `auto_cancel` 이면 이미 취소됨 — 할 일 없음.
- `auto_cancel_failed` 이면 **포트원 콘솔에서 직접 취소**하고, 고객이 문의하면 "결제가 정상 금액이 아니어서 취소했어요. 다시 구매해 주세요."

### H. 카드사 분쟁 (차지백) — `summary` 에 `dispute`
- 포트원 웹훅 `Transaction.DisputeCreated` 가 오면 서버가 **이용권을 자동으로 막아요**.
- 포트원 콘솔에서 분쟁 내용 확인 → 소명 자료 제출: 결제 일시, 구매 페이지의 환불 제한 동의(필수 체크), 이용권 등록 기록(`find` 의 기기 수 · 기록), 약관 링크.
- 고객이 실제로 결제를 모른다(도용) → 환불 처리하고 막힌 채로 둠(P).
- 분쟁이 고객 승소로 끝나면 그대로, 가맹점 승소면 `restore <키> "분쟁 종료"`.

### I. "예전부터 쓰던 사람인데 결제 화면이 떠요"
- 결제를 켜기 전에 켠 기기는 서버가 기록해 두고 계속 무료예요. 이 화면이 뜨는 경우:
  - 결제를 켠 뒤 처음 켬(그 전엔 설치만 하고 안 켬) / 컴퓨터를 바꿈 / 운영체제 재설치.
- 확인할 수 있는 것: 예전 [의견 보내기] 기록, 고객이 보내 준 예전 화면 · 데이터 파일 날짜 등. **애매하면 믿어 줘요.**
- 처리: `grant <메일 또는 -> "먼저 쓰던 사람 복구: <근거>"` → 키를 보내 [이용권 키가 있어요]에 넣게.
- 답장:
  > 예전부터 써 주셔서 감사해요. 무료로 쓰실 수 있게 이용권 키를 드릴게요: ESSAY-…

### J. "인터넷에 연결한 뒤 이용권을 확인해 주세요" 화면
- 60일 넘게 인터넷 연결 없이 쓰면 한 번 확인을 요구해요. 인터넷 연결 후 [다시 확인].
- 연결돼 있는데도 계속 뜬다 → 회사 · 학교 방화벽이 `api.essay.win` 을 막는 경우. 다른 네트워크(휴대폰 테더링)로 한 번만 확인하면 다시 60일.

### K. 영수증 · 현금영수증 · 세금계산서
- 카드 영수증: 결제 대행사 · 카드사 앱에서 확인(포트원 콘솔에서 영수증 링크도 확인 가능).
- 간이과세자는 세금계산서를 발행하지 못할 수 있어요(직전 연도 공급대가 4,800만 원 미만). 사업자 고객이 요청하면 "간이과세자라 세금계산서 대신 카드 매출전표로 증빙해 주세요."
- 과세 유형이 바뀌면 이 항목을 고친다.

### L. 미성년자 결제 취소
- 만 19세 미만이 법정대리인 동의 없이 결제한 경우 본인 또는 부모가 취소할 수 있어요. 나이를 증명하는 서류를 요구하지 말고(개인정보), 요청 내용이 그럴듯하면 전액 환불.
- `refund <결제번호> "미성년자 법정대리인 취소"`

### M. 키 공유 · 재판매 · 키 공개 발견
- 신호: 같은 키로 기기 초기화 반복, 커뮤니티에 키 공개, 중고 거래 글.
- 처리: 판매자(구매자)에게 먼저 한 번 알림 → 계속되면 `revoke <키> "공유: <근거 링크>"`. 공개된 키는 바로 막고, 원래 구매자에게는 새 키를 `grant` 해 줌(본인 확인 후).
- 환불은 하지 않아요(약관 1항: 양도 · 재판매 · 공개 금지).

### N. 개인정보 삭제 · 열람 요청
- 메일 삭제: `forget <메일>` → 주문 · 이용권에서 메일만 지워요. 결제 기록(결제 번호 · 금액 · 시각)은 전자상거래법상 5년 보관.
- 열람: `find <메일>` 결과에서 그 사람 정보만 정리해 보내요(다른 사람 정보가 섞이지 않게).
- 메일을 지우면 나중에 키를 메일로 찾기 어렵다고 꼭 안내.

### O. 앱 오류 · AI 문제 (결제와 별개)
- [의견 보내기] · 오류 보고는 `guides/서버-안내.md` 의 관리 주소로 확인. 결제와 무관한 문제도 이용권 고객이면 우선 처리.
- AI 한도 · 로그인 문제는 앱의 F1 도움말 내용으로 안내.

### P. 도용 카드 결제 · 수사 요청
- 카드 주인이 "내가 결제한 적 없다" → 카드사 연락이 오면 즉시 `refund` + 막힌 상태 유지.
- 수사기관 요청은 공문으로만, 필요한 최소 정보(결제 번호 · 시각 · 금액 · 메일)만.

### Q. 가격 · 할인
- 정가 4,900원, 지금 3,900원. 가격이 바뀌어도 이미 산 이용권의 차액은 돌려주지 않아요(약관 1항).
- 학생 할인 · 단체 구매 문의 → 여러 개가 필요하면 `grant` 로 키를 만들어 계좌이체로 받는 방식은 쓰지 않아요(현금 거래 기록 · 영수증 문제). 구매 페이지에서 각각 결제하도록 안내.

### R. 서버 · 결제 대행사 장애
- 앱은 등록증으로 인터넷 없이도 열리니 기존 사용자는 영향이 거의 없어요.
- 새 구매가 안 될 때: `docs/app-config.json` 의 `notice` 에 "지금 결제가 잠시 안 돼요. 곧 고칠게요." 를 넣고 push(앱 홈에 공지). 고친 뒤 비움.
- 장애 중 결제가 됐는데 키가 안 나온 사람: 매일 대사(서버 `reconcile`)가 3일 안 결제를 다시 확인해요. 문의가 오면 `recheck`.

## 3. 매일 · 매주 할 일
- **매일**: `cs.sh summary` → 새 의견 · 오류 확인, `auto_cancel_failed` · `dispute` 가 있으면 G · H 처리.
- **매주**: `cs.sh orders` 로 매출 · 환불 · 실패 비율 보기. 실패(`failed`)가 많으면 결제 대행사 쪽 문제를 의심하고 포트원 콘솔 확인.
- **매달**: 포트원 정산 금액과 `orders` 의 `revenue` 비교(차이가 나면 `recheck`).
